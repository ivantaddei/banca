# 🚀 Core Development Principles (100-core)

## 👶 Baby Steps™
Divide cada tarea en el cambio más pequeño posible y valídalo antes de seguir. No intentes resolver el problema completo de una sola vez; construye incrementos verificables.

## 🧪 Test-First
Cuando agregues lógica de negocio, escribe primero el test. El código debe escribirse solo para que el test pase a verde. Si el proyecto no tiene un framework de testing configurado, propón uno antes de empezar con lógica compleja.

## 🎯 No Side-Quests
Haz exactamente lo que se te pide en el ticket o tarea actual. Si identificas una mejora necesaria, un bug no relacionado o una refactorización técnica fuera de alcance:
1. Registra la observación en un `TODO` en el código o en `.ai/MEMORY.md`.
2. No lo implementes ahora.
3. Mantén el foco en la tarea asignada.
